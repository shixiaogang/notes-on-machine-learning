\section{广度优先遍历}
\label{sec:graph-bfs}

给定一张图和一个起点，最基本的问题是：从起点出发能走到哪些顶点，走到每个顶点最少要经过几条边，又该沿哪条路线走。广度优先遍历按离起点的远近逐层访问顶点，一次就回答这三个问题。

\subsection{问题与思路}
\label{sec:graph-trav-bfs-problem}

输入是图$\mathcal G=(V,E)$的邻接表和一个起点$s\in V$。记$\operatorname{dist}(s,v)$为从$s$到$v$的路径所含的最少边数，有向图中路径沿弧的方向；$v$从$s$不可达时约定$\operatorname{dist}(s,v)=+\infty$。对每个顶点$v$，我们要知道它是否从$s$可达；若可达，$\operatorname{dist}(s,v)$是多少，以及一条恰好用$\operatorname{dist}(s,v)$条边从$s$走到$v$的路线。

按定义逐条检查路径是行不通的。从$s$到$v$的路径可能极多，而且路径越长，种类增长越快；即使只想知道最少边数，也不能把所有路径列出来再比较。

不枚举路径，可以按距离把顶点分层。距离为$0$的只有$s$自己，距离为$1$的恰好是$s$的邻居。距离为$2$的顶点不在前两层，却与第$1$层某个顶点相邻：从$s$走两条边能到达它，一条边到不了。一般地，前$k$层找全以后，第$k+1$层就是与第$k$层相邻、但还没出现过的顶点。于是从第$0$层开始，每次由当前层找出下一层，直到某一层为空。

一个顶点可能与上一层的多个顶点相邻，也可能与本层或更早的顶点相邻，所以它只能在第一次被找到时归入某一层，之后再遇到就跳过。找到它时顺手记下是从哪个顶点找到的，沿这些记录往回走，就能恢复一条路线。

\subsection{算法实现}
\label{sec:graph-trav-bfs-algorithm}

逐层推进不必真的维护一层层的列表，一个先进先出的队列就够了：先进入队列的顶点先展开，第$k$层的顶点全部展开完之前，第$k+1$层的顶点只在队尾排队。算法维护四项状态：
\begin{itemize}
  \item 发现标记：顶点是否已经被找到；
  \item 队列$Q$：已经发现、但邻居尚未检查的顶点；
  \item 边数距离$d(v)$：$v$被找到时所在的层号；
  \item \term{父指针}（parent pointer）$p(v)$：$v$是在展开哪个顶点时第一次被找到的。
\end{itemize}
初始时只有$s$被发现，$d(s)=0$，$p(s)$为空，$Q=[s]$；其余顶点未发现，$d(v)=+\infty$。此后每一轮从队首取出一个顶点$u$，依次检查它的邻居。未发现的邻居$v$属于$u$的下一层：立即把它标记为已发现，写入$d(v)=d(u)+1$和$p(v)=u$，放到队尾。已发现的邻居则跳过。队列变空时，从$s$可达的顶点都已找到。这种按层访问的过程称为广度优先遍历，也常称\term{广度优先搜索}（breadth-first search，BFS）。

\begin{algorithm}[广度优先遍历]
\label{alg:graph-trav-bfs}
输入：图$\mathcal G=(V,E)$的邻接表，起点$s\in V$。输出：距离$d(v)$与父指针$p(v)$，$v\in V$。
\begin{enumerate}
  \item 标记$s$为已发现，置$d(s)=0$、$p(s)$为空，令$Q=[s]$；其余顶点未发现，$d(v)=+\infty$。
  \item 当$Q$非空时，取出队首$u$，按邻接表依次读取$u$的邻居$v$（有向图只读出邻居$v\in N^+(u)$）。若$v$未发现，立即标记$v$为已发现，置$d(v)=d(u)+1$、$p(v)=u$，并把$v$放到队尾；若$v$已发现，跳过。
  \item 队列为空时停止。
\end{enumerate}
\end{algorithm}

“只在第一次被找到时归层”要靠入队时就标记来落实。两个已发现的顶点可能共享一个尚未发现的邻居；若等到出队时才标记，这个邻居会被两个顶点各放入队列一次，距离和父指针也可能被改写。入队即标记，每个顶点就至多入队一次。

\paragraph{执行过程}
在第~\ref{sec:graph-basic-concepts}节的贯穿四点图上，以$1$为起点，并约定按编号从小到大读取邻居。图~\ref{fig:graph-trav-bfs-queue}(b)逐行列出了每次出队后的队列。初始$Q=[1]$。取出$1$时发现$2,3$，写入$d(2)=d(3)=1$、$p(2)=p(3)=1$，队列变为$[2,3]$。取出$2$时，邻居$1,3$都已发现，只有$4$是新的，写入$d(4)=2$、$p(4)=2$，队列变为$[3,4]$。取出$3$时，邻居$1,2,4$全部已发现，$4$不会第二次入队，队列变为$[4]$。最后取出$4$，没有新顶点，队列为空，算法停止。图~\ref{fig:graph-trav-bfs-queue}(a)把各顶点按$d$值分到三层，蓝色箭头就是父指针所指的边。

\paragraph{路线的恢复}
要得到从$s$到已发现顶点$t$的路线，从$t$出发反复取父指针，直到回到$s$，再把得到的顶点序列反转。在上例中，$4$的父指针是$2$，$2$的父指针是$1$，反转后得到路线$1\to2\to4$，恰有$d(4)=2$条边。父指针总是指向更早发现的顶点，所以回溯不会绕圈，一定在有限步内回到$s$。若$t$始终未被发现，即$d(t)=+\infty$，算法应报告$t$从$s$不可达，而不能输出任何路线。

路线并不唯一。若改为先读$3$再读$2$，取出$1$后队列为$[3,2]$，$4$在展开$3$时被发现，父指针变成$p(4)=3$，路线变成$1\to3\to4$。两条路线不同，边数却都是$2$：改变同层顶点的处理次序可能改变父指针，但下面的定理表明它不改变距离。

\subsection{算法分析}
\label{sec:graph-trav-bfs-correctness}

\paragraph{正确性}
算法只在顶点第一次被发现时写入$d(v)$，以后不再修改。正确性的关键在于，这个“第一次”恰好发生在最短的距离上。

\begin{theorem}[广度优先遍历的距离]
\label{thm:graph-trav-bfs-distance}
设对有限图$\mathcal G$和起点$s$执行算法~\ref{alg:graph-trav-bfs}。则对每个顶点$v$，$d(v)=\operatorname{dist}(s,v)$；当$v$可达时，沿父指针从$v$回到$s$的路线恰有$d(v)$条边。
\end{theorem}

\begin{proof}
先说明$d(v)$不会小于真实距离。若$d(v)$有限且$v\neq s$，则$d(p(v))=d(v)-1$，沿父指针每退一步距离减一，$d(v)$步后回到$s$。反转这串顶点就得到一条从$s$到$v$、恰有$d(v)$条边的路线，所以$d(v)\geq\operatorname{dist}(s,v)$。

再说明队列中的距离值有一个固定的形状：从队首到队尾不减，且最大值与最小值至多相差$1$。初始队列只有$s$，满足这一点。设某时刻队列中的值为若干个$k$后接若干个$k+1$，取出的队首$u$有$d(u)=k$，新加入的顶点距离都是$k+1$，并放在队尾，形状仍然保持。由此可知，顶点出队时的距离值按时间不减。

最后对$\delta=\operatorname{dist}(s,v)$归纳，证明有限距离的顶点都会被发现且$d(v)\leq\delta$。$\delta=0$时$v=s$。设$\delta\geq1$，并设距离小于$\delta$的顶点都已满足结论。取一条从$s$到$v$的最短路径，记其倒数第二个顶点为$x$，则$\operatorname{dist}(s,x)=\delta-1$，由归纳假设$x$被发现且$d(x)=\delta-1$。$x$入过队，就一定在某一时刻出队并检查邻居$v$。若此时$v$尚未发现，就得到$d(v)=d(x)+1=\delta$；若$v$已经被发现，则发现它的顶点$u$出队不晚于$x$，按上一段的单调性$d(u)\leq d(x)$，于是$d(v)=d(u)+1\leq\delta$。两个方向合起来得到$d(v)=\operatorname{dist}(s,v)$。不可达的顶点没有任何从$s$出发的路线，第一段说明它不可能得到有限的$d$值。
\end{proof}

证明第二段的队列形状把“逐层推进”变成了可以检验的事实：处理第$k$层时只会首次发现第$k+1$层的顶点，而它们全部排在第$k$层之后。最短路径上的倒数第二个顶点$x$比$v$少一层，一定先被展开，所以$v$不会拖到更远的层才被发现。

\paragraph{复杂度}
以邻接表存储时，每个顶点至多入队、出队各一次，出队时把它的邻接表读一遍，因此每条邻接记录只被检查常数次。无向图的邻接记录共$2m$条，有向图的出邻接记录共$m$条，总时间为$O(n+m)$。发现标记、距离、父指针和队列各占$O(n)$额外空间。这一结论依赖“列出邻居的代价与度数成正比”。若改用邻接矩阵，找出一个顶点的邻居要扫描一整行，$n$个顶点共扫描$n^2$个位置，时间变为$O(n^2)$；对稀疏图，这比$O(n+m)$大得多。

\paragraph{适用范围}
广度优先遍历把每条边都算作一步，而边上带有长度时，边数最少的路线不一定总长度最小。图~\ref{fig:graph-trav-bfs-weighted}中，从$s$直接到$t$只需一条边，广度优先遍历就用这条边记录$t$，但它的长度是$5$；经过$a$的路线多走一条边，总长度却只有$1+1=2$。所以广度优先遍历只解决所有边长相等时的最短路问题。一般边长下的最短路需要比较累计长度，留到第~\ref{sec:graph-shortest-paths}节。

一次广度优先遍历也只覆盖从$s$可达的部分。遍历结束时距离仍为$+\infty$的顶点没有被访问，不能据此断言它们是孤立点，它们之间可能有很多边。要给全图的每个顶点划分连通分量，需要在外层不断换新的起点重新启动，这是第~\ref{sec:graph-connectivity-computation}节的内容。

\subsection{多源广度优先遍历}
\label{sec:graph-trav-multi-source-bfs}

有时关心的不是离某一个起点多远，而是离一组起点中最近的那个多远。例如在网格上放置若干个种子，问每个格子离最近的种子几步。给定起点集合$S\subseteq V$，要求的是
\[
\operatorname{dist}(S,v)=\min_{s\in S}\operatorname{dist}(s,v),
\]
空集上的最小值约定为$+\infty$；同时还想知道$v$离哪个起点最近。

既然只关心最近的起点，就把$S$中的所有顶点一起当作第$0$层，从这一层开始逐层推进。实现上只改初始化：$S$中所有顶点都标记为已发现、距离为$0$、父指针为空，并按任意次序全部放入队列；此后的更新与算法~\ref{alg:graph-trav-bfs}完全相同。这称为\term{多源广度优先遍历}（multi-source breadth-first search）。

它的正确性可以归结到单源情形。设想添加一个新顶点$s^*$，从它向$S$中每个顶点连一条边（有向图中连弧$s^*\to s$）。新图中任一原顶点$v$满足$\operatorname{dist}(s^*,v)=1+\operatorname{dist}(S,v)$，因为从$s^*$出发的路线第一步必然进入$S$。从$s^*$做普通广度优先遍历，第一次出队就把$S$中所有顶点以距离$1$放入队列，此后的过程与多源版本完全相同，只是所有距离多了$1$。由定理~\ref{thm:graph-trav-bfs-distance}，多源版本输出$\operatorname{dist}(S,v)$；沿父指针回溯会停在某个起点上，它就是离$v$最近的起点之一。

图~\ref{fig:graph-trav-multi-source}是一个$3\times5$网格，相邻格子以上下左右相连，中间一个格子不属于图。两个起点放在左上角和右下角，每个格子中的数字是它到较近起点的边数。例如第一行第四个格子离左上角$3$步、离右下角$3$步，记为$3$；第一行最右的格子离右下角只有$2$步，记为$2$。若只从左上角出发，右下角的格子距离为$6$。

对每个起点各做一次广度优先遍历，回答的是另一个问题：它得到$|S|$组距离，能说出$v$到每个起点各有多远，需要$O(|S|(n+m))$时间。多源遍历只给出到最近起点的距离及对应的起点，一次只需$O(n+m)$时间。若$S$为空，队列一开始就为空，所有顶点保持未发现，与$\operatorname{dist}(\varnothing,v)=+\infty$的约定一致。图像中从种子出发的区域生长是这一机制的典型用途；判断哪些像素属于前景、怎样选择邻接规则等完整处理留到应用部分。
