\section{预算约束下的子集选择}
\label{sec:graph-budget-selection}

基数约束让每个元素占用一个名额。实际中不同传感器的价格不同，限制的往往是总花费而不是个数。逐轮贪心仍然可用，但比较的对象要改成单位成本的增益；这样改进之后，上一节的近似保证却不再成立。

\subsection{问题与思路}
\label{sec:graph-setfn-budget-problem}

给每个元素$v\in V$指定成本$c_v$，再给定总预算$B\geq0$。要求的是
\begin{equation}
  \max_{S\subseteq V}\ F(S)\qquad\text{满足}\quad\sum_{v\in S}c_v\leq B.
  \label{eq:graph-setfn-budget-problem}
\end{equation}
满足成本条件的子集称为预算可行的，这一条件称为\term{预算约束}（budget constraint）。目标函数$F$与上一节相同，改变的只是允许的子集。所有成本都取$1$、预算取$k$时，预算约束就是基数约束，所以本节的问题是上一节的推广。

成本为零的元素需要先单独处理。零成本元素不占预算，若$F$单调，把它们全部加入不会降低目标，可以在开始时一次放进集合；若$F$不单调，它们是否值得加入要看增益的正负。以下设所有成本为正。另外，成本超过$B$的元素不可能出现在任何可行集合中，可以预先删去。

在传感器实例中取成本$c_a=4$、$c_b=3$、$c_c=4$、$c_d=1$，预算$B=7$。预算可行的子集共有$10$个：空集、四个单元素集，以及$\{a,b\}$（成本$7$）、$\{a,d\}$（$5$）、$\{b,c\}$（$7$）、$\{b,d\}$（$4$）、$\{c,d\}$（$5$）；三元及以上的子集成本都超过$7$。枚举得最优集合为$\{b,c\}$，覆盖$16$格。与$k=2$的基数约束相比，$\{a,c\}$成本为$8$，现在不可行了；而$\{a,b\}$在两种约束下都可行。选择的个数不再直接决定资源消耗，每次加入元素前都要检查剩余预算。

把上一节的贪心原样搬过来，就是每轮在付得起的元素里选增益最大的。这样做会偏爱昂贵的元素：一个元素增益大，可能只是因为它贵，而它占去的预算本可以换来更多增益。预算是按成本消耗的，所以更合理的比较是每单位成本带来多少增益，即比值$\Delta(v\mid S)/c_v$。每轮选比值最大且付得起的元素，直到剩余预算放不下任何元素，或者付得起的元素都不再带来增益。

\subsection{算法实现}
\label{sec:graph-setfn-ratio-greedy}

成本$c_v$、预算$B$和求值规则在运行前给定，运行中不变，不算状态。与上一节相比，算法多记录剩余预算，并且每轮只在付得起的元素中比较。算法维护四项状态：
\begin{itemize}
  \item 已选集合$S$：初值为空集；
  \item 剩余预算$R=B-\sum_{v\in S}c_v$：初值为$B$；
  \item 当前值$F(S)$：初值由一次求值得到$F(\varnothing)$，此后每轮加上选中元素的增益；
  \item 本轮增益：每个付得起的未选元素$v$相对于当前$S$的增益$\Delta(v\mid S)$，每轮重新计算。
\end{itemize}
初始化令$S=\varnothing$、$R=B$，并求值一次得到$F(\varnothing)$。每一轮做四件事：
\begin{itemize}
  \item 列候选：记$Q=\{v\in V\setminus S:c_v\leq R\}$为付得起的未选元素；若$Q$为空，停止；
  \item 求增益：对每个$v\in Q$求值，得到$\Delta(v\mid S)$；若这些增益全为零，停止；
  \item 选择：取比值$\Delta(v\mid S)/c_v$最大的$v$，比值相同时取编号最小者；
  \item 更新：令$F(S)\gets F(S)+\Delta(v\mid S)$，再令$S\gets S\cup\{v\}$，$R\gets R-c_v$。
\end{itemize}
停止条件因此有两个：剩余预算放不下任何未选元素，或者付得起的元素都不再增加目标。

\begin{algorithm}[预算约束下的单位成本贪心]
\label{alg:graph-setfn-ratio-greedy}
输入：有限底集$V$（元素已编号），正成本$c_v$，预算$B\geq0$，单调非减集合函数$F$的求值规则。输出：预算可行的集合。
\begin{enumerate}
  \item 令$S=\varnothing$，$R=B$，记录$F(\varnothing)$。
  \item 记候选集合$Q=\{v\in V\setminus S:c_v\leq R\}$。若$Q$为空，停止。
  \item 对每个$v\in Q$计算$\Delta(v\mid S)$。若这些增益全为零，停止；否则取比值$\Delta(v\mid S)/c_v$最大的$v$，比值相同时取编号最小者。
  \item 令$S\leftarrow S\cup\{v\}$，$R\leftarrow R-c_v$，回到第2步。
\end{enumerate}
\end{algorithm}

\paragraph{执行过程}
在$B=7$的实例上，表~\ref{tab:graph-setfn-ratio-trace}逐轮记录状态。
\begin{itemize}
  \item 第$1$轮：$R=7$，四个元素都付得起，增益是各自的覆盖量，比值为$a{:}10/4=2.5$，$b{:}8/3\approx2.67$，$c{:}8/4=2$，$d{:}1/1=1$。选$b$，$R=4$。
  \item 第$2$轮：$Q=\{a,c,d\}$，增益相对于$\{b\}$重新计算。$a$只补上第$5$、$6$列的$4$格，比值$1$；$c$与$b$不重叠，增益$8$，比值$2$；$d$那一格已被$b$覆盖，增益$0$。选$c$，$R=0$。
  \item 第$3$轮：没有成本不超过$0$的元素，$Q$为空，停止。
\end{itemize}
输出$\{b,c\}$，覆盖$16$格，恰为枚举最优值。

\paragraph{最佳单元素比较}
单位成本规则也有自己的偏差：它可能先选几个便宜的小元素，把预算切碎，使一个昂贵但价值很高的元素再也放不进去。一种简单的补救是在算法结束后增加一步：计算每个可行单元素的值$F(\{v\})$（$c_v\leq B$），输出$S$与最佳单元素中函数值较大的一个。这只需另外$n$次求值。在$B=7$的实例中，最佳单元素是$\{a\}$，覆盖$10$格，小于$16$，输出仍是$\{b,c\}$。这一检查只是一个具体策略；本节没有给出它的分析，因此不附加一般的近似比例。

\subsection{算法分析}
\label{sec:graph-setfn-budget-limits}

\paragraph{可行性}
算法始终保持$R=B-\sum_{v\in S}c_v\geq0$：初始时$R=B\geq0$；每轮只从$Q$中选元素，而$Q$中元素的成本不超过$R$，减去后$R$仍非负。所以输出总是预算可行的。

\paragraph{停止性}
每轮加入一个新元素，至多执行$n$轮就会停止。停止时有两种原因：没有付得起的元素，或者付得起的元素都不再增加目标；对单调函数，后一种情形下再加入任何付得起的元素都不会提高函数值。

\paragraph{复杂度}
第$t$轮的候选元素不超过$n-t+1$个，所以求值次数不超过$n+(n-1)+\cdots+1=n(n+1)/2$，再加开始时的一次$F(\varnothing)$；附加最佳单元素比较时另加$n$次。上面的实例做了$1+4+3=8$次求值。若一次求值的代价为$\tau$，总代价为$O(n^2\tau)$。

\paragraph{适用范围}
单位成本规则在上面的实例中表现很好，但它本身没有任何固定比例的保证。

\begin{example}[比值规则的失效]
\label{ex:graph-setfn-ratio-failure}
底集$\{u,w\}$，预算$B=100$。$u$的成本为$1$、价值为$2$，$w$的成本为$100$、价值为$100$，目标取模函数$F(S)=\sum_{v\in S}(\text{价值})$。它单调，也是次模的。

比值规则第$1$轮比较$2/1=2$与$100/100=1$，选$u$；剩余预算$99<100$，$w$付不起，算法停止，得$F(\{u\})=2$。最优选择是$\{w\}$，$F=100$。见图~\ref{fig:graph-setfn-budget-ratio-failure}。把$w$的成本、价值与预算同时换成任意大的$M$，比值规则仍先选$u$，得到$2$而最优值为$M$，比例$2/M$可以任意小。
\end{example}

  \centering
  \includegraphics[width=109.146mm]{figures/01-basic-mathematics/04-graphs/tikz/c4-budget-ratio-failure/figure.pdf}
  \caption{比值规则的失效例。横条长度代表预算$100$。上行：比值规则先选单位价值较高的$u$（黄色，成本$1$，为便于观察略加宽），剩余$99$个单位（斜线）放不下成本$100$的$w$，总价值$2$。下行：最佳单元素$w$恰好用满预算，总价值$100$。}
  \label{fig:graph-setfn-budget-ratio-failure}
\end{figure}

这个例子的目标是模函数，从而单调且次模，满足上一节定理的全部函数条件。比值规则仍不能继承那里的保证，原因在于上一节差距论证的关键一步没有对应物。那里最优集合的至多$k$个元素在每一轮都仍然可选，所以当前最好的元素至少补上差距的$1/k$。预算约束下，选进一个便宜元素就可能让最优集合中的元素再也付不起：例中选了$u$以后，差距是$100-2=98$，而最优集合唯一的元素$w$已经放不进剩余的$99$个单位，可选的元素一个也没有，差距一点也补不上。最佳单元素比较能修复这个例子，但修复一个例子不构成一般保证；有严格保证的预算选择算法需要另外的枚举或修正机制及其证明，本书不展开。

\paragraph{结果检验}
小实例可以枚举全部预算可行子集，核对总成本、函数值以及与最优值的差距：$B=7$时比值规则的$\{b,c\}$与枚举最优一致，总增益规则的$\{a,b\}$差$4$格。大实例无法枚举时，至少应报告剩余预算、最终目标值、最佳单元素的值和总求值次数；若逐轮规则的结果不如最佳单元素，往往就是出现了示例~\ref{ex:graph-setfn-ratio-failure}那样预算被小元素切碎的情形。

\paragraph{与基数约束贪心的比较}
两种贪心的状态与更新几乎相同，差别只在选择依据换成单位成本的增益，停止条件换成剩余预算放不下有增益的元素。对同样的单调次模目标，基数约束下有$1-(1-1/k)^k$的保证，预算约束下简单的比值规则却可以任意差：约束的形式本身就决定算法能否得到保证。
