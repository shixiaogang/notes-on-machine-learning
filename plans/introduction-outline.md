## 章节定位与叙述主线

本章回答三个问题：什么是学习，什么是机器学习，以及一个机器学习系统如何从经验中获得处理新问题的能力。

叙述顺序为：**什么是机器学习（从学习谈起，介绍历史、定义与三要素） → 垃圾邮件分类的完整案例 → 任务、经验、性能度量的概念整理**。

垃圾邮件案例是本章的重心，负责让概念在具体过程中首次出现；之后的三节负责给出更一般的定义、分类和适用边界，避免重复讲解案例。模型、参数、假设空间和归纳偏置在案例中介绍，不另设模型节。机器学习范式从任务与应用场景自然引出，模型体系与可学习性分别交给后续“模型简介”章和“机器学习理论”部分展开。

## 1.1 什么是机器学习

### 1.1.1 什么是学习

- 从识别事物、学习技能、根据反馈调整行为等现象切入，提炼经验、变化和能力三个观察角度，区分暂时表现变化与相对持久的学习效果。
- 提出本章的核心疑问：经历过一些情形，为什么可能更好地处理尚未经历的情形？
- 从哲学视角简述经验在知识获得中的作用，以及已有概念和假设如何参与理解经验；区分由具体经验形成一般判断的归纳与根据既定前提推出结论的演绎。
- 借休谟关于经验推断的讨论，引出“过去的观察为何能够支持对未知的判断”，为后文的归纳偏置与泛化埋下伏笔；不展开哲学史争论。参考[《人类理解研究》第四节](https://davidhume.org/texts/e/4)。
- 从心理学视角，以条件作用、反馈学习和认知表征为例，说明学习可以从可观察行为或内部知识与表征的变化来研究。定义讨论参考[De Houwer 等关于学习定义的论文](https://biblio.ugent.be/publication/3107030)。

### 1.1.2 从学习到机器学习

- 说明人类学习与机器学习的联系和类比边界，过渡到机器学习的历史探索。
- 从“逐条编写判断规则”的困难，说明为什么希望计算机利用经验改进表现。
- 以McCulloch--Pitts神经元、图灵的儿童机器设想、Rosenblatt感知机和Samuel跳棋程序说明早期探索的不同路线。
- 用Vapnik--Chervonenkis学习理论、误差反向传播与深度学习连接统计学习、神经网络和表示学习的发展；引用均追溯到原始论文。
- 强调经验驱动的改进仍然依赖人设计任务、表示、学习规则和评价方式。
- 分别说明机器学习与人工智能、数据挖掘、统计学与概率论、优化、算法与系统、信息论与信号处理、控制理论、认知与神经科学以及应用领域的联系与边界。

### 1.1.3 机器学习的定义

- 采用 Mitchell 的经典定义：如果程序通过经验，在某类任务上的表现按指定性能度量得到改善，就称其在该任务上进行了学习。参考[Mitchell《Machine Learning》及作者提供的资料](https://www.cs.cmu.edu/~tom/mlbook.html)。
- 解释定义的目的：把“机器是否学会了”转化为可以描述和检验的问题。
- 从定义中提取三个要素：**任务**说明希望系统完成什么，**性能度量**说明如何判断完成得好不好，**经验**说明系统从哪些观察、数据或交互反馈中学习。
- 说明三者必须结合描述；经验可以来自已有数据，也可以来自环境交互，不限于人工标注的数据集。
- 说明“改善”应通过适当评价来检验，不意味着每增加一条经验，性能都会单调提高。

## 1.2 例子：垃圾邮件分类

**开篇（不设小节标题）：明确任务、性能度量与经验。**

- 任务：根据一封邮件可用的信息，判断其是否为垃圾邮件。
- 性能度量：先用准确率（分类正确的比例）建立直觉，再指出误拦正常邮件与漏放垃圾邮件的代价不同，详细指标留到1.5节。
- 经验：历史邮件及其人工标注；约定垃圾邮件为正类，标签为1，正常邮件标签为0。
- 用一张三要素对应表固定问题设定，并给出简单规则或多数类预测作为比较基线。

### 1.2.1 从邮件到样本与特征

- 区分原始邮件、输入表示、标签、单个样本与数据集。
- 先说明邮件可能包含发件人、文本、链接、附件、邮件头和历史交互等多种特征，再明确本例假设标签与促销词次数、链接数量两个特征密切相关。
- 给出部分历史邮件数据表，列出邮件片段、特征取值、人工标签与所属数据子集，介绍样本数、特征维度与特征取值；明确数据为教学构造。
- 先划分训练集、验证集和测试集；任何需要从数据估计的词表或预处理规则，只在训练集上拟合。

### 1.2.2 对问题进行建模

- 将建模过程连成一条主线：确定输入与输出 → 选择候选模型 → 定义预测错误的代价 → 形成参数学习的目标。
- 先假设分类结果与特征之间存在可由线性得分描述的关系，再给出逻辑分类模型和阈值规则。
- 解释输入、输出、权重、偏置项和参数向量，以及“选择模型形式”和“确定参数”的区别。
- 介绍假设空间：模型形式规定了可供选择的一组候选规则。
- 从选择哪些特征、采用何种模型形式切入归纳偏置，说明有限训练数据通常不能唯一确定对新邮件的判断。
- 从一次预测与真实标签的差异引入损失函数。
- 为上述概率输出配一个简单的二分类交叉熵损失，直观解释为何“自信但错误”的预测受到更大惩罚。
- 将训练样本上的平均损失定义为经验风险，给出经验风险最小化的基本形式。
- 区分用于训练的损失与用于报告任务表现的性能度量，两者可以不同。
- 这里只解释模型和训练目标怎样表达问题；逻辑回归的系统推导留给后续模型章节。

### 1.2.3 根据历史邮件进行训练

- 给出训练过程：初始化参数 → 计算预测 → 计算损失 → 根据优化规则更新参数 → 重复至停止。
- 给出初始化、第一次更新和最终检查点的参数及平均训练损失，说明“参数学习”具体改变了什么；只解释更新的作用，不展开梯度推导。
- 区分模型、学习算法与训练得到的模型；说明实际优化通常是在近似求解训练目标。
- 以学习率、训练轮数等引入超参数，通过验证集选择配置；测试集不参与选择。
- 用简短伪代码串起数据、模型、损失、参数更新和验证步骤。
- 给出训练记录表，对照初始化、一次参数更新和最终选定模型的参数及平均训练损失，让读者看到训练实际改变了什么。
- 用实际运行记录绘制训练集与验证集损失随迭代变化的曲线，标出选定模型的迭代位置；说明训练集参与参数更新、验证集参与配置选择。

### 1.2.4 对新邮件进行预测

- 完整展示一封新邮件经过相同预处理、特征表示、模型计算和阈值判断，得到预测结果的过程。
- 将使用已学模型计算输出的过程称为推理，本例中的推理结果是垃圾邮件概率估计和类别预测。
- 说明在本例的离线训练设定下，预测时使用已经学到的参数，不进行参数更新，也不需要预先知道新邮件的真实标签。
- 给出新邮件推理结果表：邮件片段、特征、概率估计、判断阈值与预测类别；各行结果都由上节选定模型计算，不预填真实标签。

### 1.2.5 模型的评估

- 在独立测试集上评估，并与基线比较；说明训练集上的好成绩不足以证明对新邮件有效。
- 展示带真实标签的测试结果表，对照预测与标签，标出正确分类、误拦与漏放；与上一小节新邮件推理时标签未知的情形区分开来。
- 汇总本模型与基线在相同测试集上的准确率、误拦数量和漏放数量；这些结果在1.5节继续用于混淆矩阵和评价指标的介绍。
- 定义泛化，直观介绍过拟合与欠拟合，区分优化训练目标与改善泛化表现。
- 解释训练数据与未来邮件之间需要具备一定联系；用邮件表达方式变化说明分布变化可能导致失效。
- 简述增加有代表性的数据、控制模型复杂度与正则化的作用，不展开理论保证。
- 用简短回顾收束案例，串起任务、数据、模型、学习过程和评价；之后分别从任务、数据和性能度量三个角度进一步整理。

## 1.3 任务

本节按“应用场景中的任务 → 常见任务类型 → 任务与学习范式”展开。三个小节分别从具体应用、跨领域任务形式和经验组织方式回答“系统要完成什么”。

### 1.3.1 应用场景中的任务

- 分别介绍自然语言处理、图像处理、推荐与搜索应用，说明各类系统的输入、输出和典型处理环节。
- 指出一个应用系统往往组合多个任务，例如搜索包含候选召回与排序，推荐包含偏好估计、排序和长期反馈。
- “推荐与搜索”按“分别定义 → 区别与联系 → 具体学习任务”展开。用电影首页推荐与“适合孩子看的太空电影”查询作对照，说明需求的表达方式不同，但两者都要匹配内容与需求、筛选候选并排列结果，也可以共享信息与反馈。
- 依次解释查询理解、候选匹配、评分与行为预测、排序与重排序、序列推荐及序贯决策。每项交代输入、输出和可采用的任务形式，区分应用目标、处理环节与学习方法；说明点击反馈受展示位置影响，检索与重排序也可使用明确规则。参考[Manning等人的教材](https://nlp.stanford.edu/IR-book/)及[Google推荐系统概述](https://developers.google.com/machine-learning/recommendation/overview/types)。
- 简述生命科学、自动化与控制系统、语音处理中的分类、回归、聚类、生成、序列预测与序贯决策问题，说明应用场景与任务形式的区别。

### 1.3.2 常见任务类型

- 用输入对象、输出形式和目标要求描述任务：判断邮件类别与识别图片类别都可归为分类，预测评分可表述为回归，排列推荐候选可表述为排序。
- 通过对照表整理分类、回归、排序、聚类、降维、生成与序贯决策；每种任务说明典型输出、主要目标和一个前文例子。
- 分类补充二分类、多分类与多标签的区别；指出聚类、生成与序贯决策不必都写成同一种单次预测问题。
- 区分逐点、成对和列表排序方法，说明任务转化可以借用分类或回归方法，但最终仍要按排序目标评价。
- 说明目标检测、推荐排序等应用怎样组合多项任务，以及任务分解和转化必须保留原问题关心的信息。

### 1.3.3 任务与学习范式

- 沿着“这些系统怎样从经验中学会完成任务”追问：有没有人工给出的答案，能否从数据自身构造学习信号，是否能通过交互获得反馈？
- 对应介绍监督学习、无监督学习、自监督学习与强化学习，沿用人工标注邮件、无标签文档分组、文本补全和根据奖励调整推荐决策等例子。
- 从邮件或用户偏好随时间变化引出持续学习，只介绍持续接收经验和保留已有能力的基本问题。
- 指出这些名称涉及不同划分维度，可以组合；学习范式由经验与学习过程的组织方式决定，不能仅凭“文本”或“推荐”等应用名称判断。详细体系交给后续“学习范式简介”章。
- 收束场景、任务和范式的关系：同一种任务可以服务不同应用，同一应用可以组合多种任务，而同类任务可能在不同学习范式下完成。

## 1.4 经验

暂不分编号小节，从可供学习使用的样本、反馈和交互说明经验，再依次整理其数据表示、分布与质量，以及划分与使用方式。

**样本、特征、标签与数据集。**

- 整理案例中已有的定义，区分原始对象与用于模型的表示。
- 简述表格、文本、图像和序列等数据形式，以及有标签与无标签数据。
- 说明特征可以由人设计，也可以通过学习获得；标签只是一类学习信号，经验还可以包括交互轨迹与奖励。

**有限数据与数据分布。**

- 从“手中的邮件只是未来可能邮件的一部分”引入数据分布与抽样。
- 直观介绍独立同分布这一常用假设，并说明时间相关、用户差异等情形可能使其不适用。
- 解释样本数量、覆盖范围、标签质量、噪声和类别不平衡怎样影响学习，不作系统的数据治理展开。

**数据划分与信息泄漏。**

- 概括训练集、验证集、测试集的职责及使用顺序。
- 说明划分方式应贴近未来使用场景，随机划分并非始终合适；给出按时间或用户划分的直觉。
- 用重复邮件跨集合、从测试集拟合预处理规则等例子解释信息泄漏，以及它为何使评估过于乐观。
- 用数据划分与用途图说明训练、验证、测试各自允许参与的环节，并以时间轴示意面向未来预测时的一种划分方式。

## 1.5 性能度量

暂不分编号小节，沿“应用目标 → 具体指标 → 泛化评价”的顺序展开，继续使用1.2节得到的测试结果。

**从应用目标到评价指标。**

- 指标应反映任务目标，且评价需要与有意义的基线比较。
- 回到垃圾邮件案例，解释误拦与漏放的不同代价，以及类别不平衡时仅看准确率的局限。

**常见指标与基本取舍。**

- 以混淆矩阵为基础，给出准确率、精确率、召回率和F1值的定义。
- 用同一组可复核的分类结果计算指标，解释阈值改变如何影响误拦与漏放。
- 对回归中的平均绝对误差、均方误差作简短介绍；其他任务只说明需要相应指标，不罗列完整指标体系。

**损失、风险与泛化评价。**

- 并列区分单个样本的损失、训练集上的经验风险、目标分布上的期望风险，以及独立测试集上报告的性能。
- 说明测试结果是对特定数据与评价条件下表现的估计，不等于任意未来场景的保证。
- 提醒比较模型时保持测试数据、评价口径和基线一致；系统评估方法留待后文。

## 1.6 本章小结

- 用一段话回顾：经验在给定假设和学习规则下塑造模型，效果通过任务上的性能表现检验，核心关注能否推广到未见情形。
- 指向后续“模型简介”“学习范式简介”两章和“机器学习理论”部分，分别承接规律如何表示、学习如何组织，以及何时能够学好。

## 写作安排

- **标题层级**：章首直接进入1.1；1.1设“什么是学习”“从学习到机器学习”“机器学习的定义”三个小节。1.2的任务、性能度量与经验直接写在节下，其后设五个小节。1.3设“应用场景中的任务”“常见任务类型”“任务与学习范式”三个小节；1.4和1.5不分编号小节。
- **篇幅重心**：1.2节约占全章三分之一；1.1节负责从跨学科的学习概念过渡到机器学习，1.3—1.5节保持定义、直觉与少量例子的深度。
- **公式控制**：核心公式围绕一个分类模型、一个损失、经验风险最小化与少量评价指标展开；不在引言中推导优化算法、泛化界或完整模型理论。
- **案例一致性**：从特征表示到测试评估沿用同一任务设定；教学构造数据、演示参数与真实实验结果须明确区分，所有数值可复核。
- **概念分工**：案例负责解释概念为何出现；任务、数据和性能度量三节负责整理定义和边界，通过交叉引用连接。模型概念集中在案例中交代，模型族的系统介绍交给后续章节。
- **术语与来源**：术语首次出现时给出中英文；历史、哲学和心理学观点按具体文献归属表述，不把某一种定义写成所有学科的共识。
