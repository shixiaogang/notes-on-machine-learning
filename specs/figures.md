# 图像规范

## 选型原则

1. 数据图（定量曲线、统计图和实验结果）用 Matplotlib，根据真实数据生成，保留数据、代码与矢量输出。
2. 一般框图（架构图、流程图和神经网络机制图等）采用“图像模型设计 + TikZ 还原”，遵循 academic-drawing 的“设计 → 渲染 → 评审”流程：先根据核实的事实与视觉要求生成设计稿，再用 TikZ 还原可编辑的节点、文字与连线。设计阶段不预设横排、列数或节点位置，用户明确提出的对齐或输出位置才作为该图偏好。
   简单几何示意图可直接用 TikZ 绘制，不必先由图像模型设计。例如卷一当前图 11.5（搬运表，`fig:information-transport-tables`）、10.3（联合分布格表，`fig:rv-dependence`）、9.14（六环与两个三角形，`fig:graph-theory-wl-local-ambiguity`）和 9.12（路径上的局部滤波，`fig:graph-theory-polynomial-locality`）。以少量点、线、基本形状或规则格表解释数学关系的同类图均适用，图号变化后按标签定位；已核实的讲解用概率值或搬运值不使其变成实验数据图。实际定量数据图仍遵循 Matplotlib 路径，复杂框图仍走模型设计与 TikZ 还原。
3. TikZ 不适合表达的写实场景、复杂纹理或概念插画，可以使用图像生成模型绘制。
4. 框图中的局部插画或图标优先复用可追溯的矢量资源，必要时嵌入设计稿裁剪或单独生成的 PNG；明确区分纯矢量与混合图。用户仅要求试绘或版本对比时可以只交付设计预览，不称为矢量终稿。
5. 不得为了节省时间把本可复现的曲线或数据图替换为截图或生成式图像。
6. 外部图像仅在无法合理重绘时使用，并记录来源、许可和必要的修改说明。

## 文件与可复现性

- 所有图像资源按 `figures/<卷目录>/<部分目录>/<生成方式>/` 归档，卷、部分目录与 `tex/` 同名。生成方式使用 `tikz/`、`matplotlib/`、`generated/`（大模型生成）或 `external/`（外部素材）；按制作方式归类，不按 PDF、PNG 等输出格式归类。
- 同一图的源文件、数据、导出文件和来源记录放在同一方法目录，复杂图组可以再设子目录。TikZ 使用的数据采样脚本随 TikZ 图源保存；导出预览不会改变图的分类。
- 跨部分共用的资源放在所属卷的 `00-shared/`，跨卷共用的工具放在 `figures/00-shared/`。仅共享一份源文件，正文引用其实际路径；不得为匹配目录重复复制素材。
- LaTeX 和生成脚本使用相对项目根目录的资源路径；移动资源时同步更新正文、绘图脚本、元数据与验证入口。脚本应自动定位项目根目录，不能依赖固定的父目录层数。
- 当前资源索引见 `figures/README.md`。历史生成与校验记录保留原日期；其中的校验值描述当时版本，不能当作当前验收结果。
- TikZ 图应保留可编辑源文件。实验图应保留绘图代码、数据来源和关键参数。
- 生成式图像应保留提示词、模型名称、生成日期和必要的后处理说明，以便重现或修改。
- 文件名使用简短、可描述内容的英文小写名称，单词间用连字符，例如 `transformer-architecture.tex`。
- 不直接覆盖仍被正文引用但含义已改变的图；应同步检查图注、标签和正文描述。

## 统一视觉风格

本节参考 academic-drawing 的 [设计要求](https://github.com/shixiaogang/skills/blob/main/academic-drawing/references/diagram/diagram-design.md)、[渲染视觉规格](https://github.com/shixiaogang/skills/blob/main/academic-drawing/references/diagram/diagram-render.md) 与 [数据图要求](https://github.com/shixiaogang/skills/blob/main/academic-drawing/references/chart/chart-draw.md)，只约束必要的配色、字体、标注与可读性。布局、节点形状和具体尺寸按图的内容决定；颜色、字体与线条参数由 `tex/styles/figure-style.tex` 及其加载的共享样式集中维护，不在单张图中另设一套。

### 框图的设计语言

下述模型参考输入、设计稿还原与风格对照适用于一般框图；直接用 TikZ 绘制的简单几何示意图仍遵循统一配色、字体、标注和可读性要求，但不强加图标底板、角色卡片、说明行或流程编号，不要求模型提示词、设计稿或两图对照。

可用 [风格品质参照](assets/diagram-style-reference.md) 作为提示词的跨主题参考；它保存用户认可的图标、标题/说明和同色浅深气质，具体机制另按事实清单核验。

- 新绘和整体重绘的框图采用有内容层次的轻盈 technical newsletter 风格。主要角色与功能模块由语义图标、同色图标底板、醒目标题和灰色短说明共同组织；机制由必要的样本、张量、公式或子模块解释。不能仅给矩形填色、统一小字，或因“简洁”删去这些层次。
- 设计阶段通过模型工具的真实图片接口提供 1–2 张相容的品质参考；优先使用用户认可风格的跨主题样例，再选 skill 图库参考。明确借鉴图标底板、标题与说明的层次、框内浅深、图形比例与留白，不复制布局或业务内容。工具不支持参考图片时记录限制并描述具体视觉观察；布局自由不等于没有风格参考。
- 提示词既要写准确事实，也要写正面的设计目标：标题与说明有字号和字形差，外壳、子模块、图标底板有同色浅深差，内部图形与文字比例协调。不能只给色值和禁用项，让模型默认退化成普通色块框图。
- 主要模块默认使用统一 Lucide outline 语义图标和同色较深的小底板。纯数学算子、无准确图标的对象，或已由样本/张量图元清楚解释的节点可省略；不为方便绘制而整图取消图标。复杂局部可按 skill 的矢量复用或混合渲染方式处理，保留来源与许可证。
- 禁止无信息的阴影、渐变和装饰性斜 3D；表达空间、通道或机制所需的几何及局部插画可保留，不把“便于 TikZ 还原”作为简化设计稿的理由。TikZ 必须保留设计稿的图标底板、标题/说明层次、内部图形与配色气质。

### 配色

- 使用白色或极浅灰背景、低饱和色块和清晰的深色文字。填充用浅色，描边与可选图标使用对应主色；辅助文字可以用灰色，但须在最终尺寸下清楚可辨。
- 新绘与整体重绘的框图、数据图共用 Lancet 2024-07 主色板（11 色及允许的固定浅底档位见上述渲染规格）。不得自行新增近似主色、调整主色饱和度或混入其他类别色板；用主色与白色的固定混合比例形成浅底。迁移须在共享样式集中定义并记录语义映射，不在单图硬编码；本次规范更新不追溯改变现有图源。
- 主色分配到主要语义节点或分组，一个框以一个色系为主；内部通过浅底、子模块与图标底板的深浅形成层次，少量其他颜色只表达独立语义，不为每个内部算子增加对比色。相邻且语义不同的独立框优先用可区分的主色；相同语义保持同色，以留白和较浅填充避免大片连续鲜艳色区，不能为相邻异色随意改变语义。
- 先记录分组与内部模块的语义层级，不机械按通用角色表染色。不同本地域或对照条件可以用不同主色区分组身份，组内同类模块继承所属组色；保持跨图一致的是已记录的同一语义映射，不能把所有“模型”或“参与方”强制连成一种颜色。主色用于细描边、图标和局部强调，大面积外壳用较浅档位，子模块与图标底板依次形成更清楚的浅深差。
- 数据图按类别、连续数值或相对中心的偏差选择离散、顺序或发散映射，热图注明色标和范围，同一组对照图保持一致的数值与颜色映射；连续色阶遵循数据图要求，不把框内浅底层次当作数值色阶。
- 颜色不能承担全部含义，至少配合直接标签、线型、形状或纹理之一。检查灰度下的关键区分；依赖色相的图还应检查常见色觉障碍下的辨识度。
- 普通连线使用中性深灰，辅助连接适当减淡。仅在需要表达特定语义时使用彩色连线，避免颜色过多或装饰性强调。

### 字体

- 既有图及数据图沿用项目字体接口；数学符号沿用 STIX2，与正文记号一致。新绘和整体重绘的框图标题采用思源黑体 Normal，必要说明、边标签与分组注解采用霞鹜文楷 Regular 灰色，英文沿用 Source Sans 3 Regular；字体与许可证须随资源保留。
- 框图标题保持 Normal、说明保持 Regular，通过字号、字族、语义主色与图标底板区分层次；数据图沿用 Regular，层级少而清楚，不把全部文字加粗。
- 框图标题比说明大一档，必要时用语义主色强化角色；主色文字对比不足时用深墨，配合图标底板保持层次。不把全图文字设成相同字号和样式。通过共享样式提供标题、说明与图标底板接口，不能在单张图内另设字体；本次只更新规范，不追溯改动既有图源、正文或现有字体实现。
- 图像模型的字体仅视为外观近似，正式图中的字体、字号、中文与数学文字由矢量排版落实；字体替换后须重新检查是否丢失标题/说明层次与整体设计感。
- 按最终排版宽度检查文字，图内文字不应小于脚注字号。拥挤时优先换行、重排或拆图，不靠继续缩小字号容纳内容；导出后检查缺字、字体替换与文字裁切。

### 标注与线条

- 标注贴近所指对象：节点内写名称，连线旁写操作或条件，分组边界处写组名。只保留识别对象、变量、方向和分组所需的短文字；不强制每个节点添加描述、图标或步骤编号。
- 名称与紧邻的短变量或维度优先同一行，例如“词元嵌入 X”“位置编码 P”“共享编码器 fθ”“本地数据 D₁”；实际排版使用正文一致的数学记号。不把单个字母、下标符号或短变量独占一行作为描述。必要说明另起一行，独立公式、多元素张量与矩阵保留自身结构；容纳短标签时先调整节点宽度，不靠缩小字号。
- 同级或对应的成组模块尽量对齐外框、标题及输入区；顺序或模块数不同的路径可用适度留白协调，不为对称添加算子、改变顺序或接错关系。输出集中于右侧只是可选布局，不能固化为全书模板。
- 不在画布中重复图号、大标题、说明段或结论。能够直接标注的对象优先直接标注；曲线或类别较多时保留必要图例，避免读者反复远距离匹配。标签使用对象名称，不以“红线”“蓝块”等颜色名称代替含义。
- 坐标轴标明变量及适用的单位；必要时说明尺度、归一化方式与实验条件。存在随机性时，优先展示误差带或误差棒并说明含义；不添加未经核实的显著性标记。
- 箭头方向、端点和线型须对应真实关系；同图中的同一线型只表达一种含义。主次连接用线宽和深浅区分，箭头、连线与标签不得遮挡节点或文字，交叉与汇合须能辨认。
- 线宽、箭头和留白以最终尺寸下的可读性为准，沿用共享样式作为起点。避免无信息价值的阴影、渐变和装饰，立体表示仅用于解释空间或张量结构。
- 默认使用统一 Lucide outline 矢量图标，无合适资源时再选统一 Font Awesome regular / outline；图标与所属框主色一致，配同色底板，保留来源与许可证。省略范围见“框图的设计语言”，不混搭多套风格或以实心装饰图标替代 outline。

## 图注与引用

- 图内只保留识别对象、变量、操作、坐标与单位所必需的短标注。补充性的示例设定、尺度说明、解释性公式和结论放入图注或正文；已经能由位置、线型或结构辨认的信息，不再重复标注。
- 每张图都应有能够独立理解的中文图注，解释图展示的对象、视觉编码和必要的实验条件。
- 图像统一使用 `\label{fig:...}`，并在正文中通过交叉引用提及；不得只写“如下图”。
- 正文应解释读者应从图中观察到什么，不重复逐字描述所有视觉元素。
- 若图像改编自外部资料，应在图注中明确注明来源或“改编自”。

## 生成式图像的质量要求

- 设计稿可展示核实后的公式、标签与拓扑，但生成模型不是事实或数值来源；设计稿不能替代真实数据图或矢量终稿中的精确表达。中文、数学符号、坐标与计数由后续矢量排版落实，不能把像素文字近似当作准确字体嵌入。
- 正式交付分别检查科学准确、读者理解、视觉质量及设计稿与矢量还原的样式一致性；逐边核对起止端点和方向，移动或重排后重查全部相关连接。对设计稿不合理的整体配色或布局先修订设计，不在还原时擅自另做一套。
- 将成图与品质参考及设计稿并排检查标题/说明字形与字号、图标与底板、框内浅深、图形比例和留白；颜色值正确、编译通过或没有错字，不能抵消设计层次消失。普通色块框图或 TikZ 还原后明显丢失设计感时须返工，不以笼统“轻盈”通过验收。
- 以最终尺寸检查单行短标注、框内色彩层次、连续色区、中文与数学显示、裁切及嵌入栅格的有效分辨率。保留设计稿、完整提示词、实际工具信息、矢量源与必要嵌入资源；未暴露的模型或参数明确注明，不伪造可复现性。
