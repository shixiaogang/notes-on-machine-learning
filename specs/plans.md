# 正文大纲与计划目录规范

本规范约束 `plans/` 的目录、内容及维护。该目录保存当前正文的结构和段落提要，入口为[正文大纲索引](../plans/README.md)。卷目以 `tex/volumes.json` 为准，章节范围和顺序以各卷实际正文入口为准。

下文关于标题层级、`paragraph` 和自然段提要的写作要求，也适用于评审稿和拟调整大纲。拟调整稿保存在用户指定的评审或草案目录中，写明基线、调整范围及尚未落实到正文的状态；不得混入 `plans/` 的当前正文大纲，也不得写成正文已经完成的内容。仅要求审读或调整大纲时，不据此修改正文。

## 目录组织

- 根目录只保留 `README.md` 总索引和各卷目录。卷目录与 `tex/` 中的卷目录同名，沿用两位序号和英文名称，例如 `plans/03-foundations/`。
- 设有部分的卷，每个部分保存一份大纲，文件名采用对应部分目录名加 `.md`，例如 `03-foundations/02-learning-theory.md`。同一部分不拆成多份章纲，也不另设重复的卷级大纲。
- 不设部分的卷直接保存一份 `outline.md`，目前为卷四和卷五；不为大纲人为增加正文不存在的部分。
- 总索引列出各卷、各部分的大纲链接和实际接入的章节数量。新增、移除或调整卷与部分时，同步修改目录、文件名、链接及数量。
- `plans/` 不存放旧版规划、独立章目映射、文献地图、研究课题、聊天讨论、审读记录、正文快照或一次性构建报告。历史版本由 Git 保存。仍有程序依赖的校验契约放入相应测试资源目录，并更新读取路径；图源、数据、生成记录与许可证按资源规范归档，清理前检查依赖。

## 大纲内容

每份大纲必须写明所属卷、部分及正文入口，使用仓库内的相对链接定位源文件，并包含以下内容：

1. **部分或卷的主线。** 说明当前正文处理什么问题，各章如何分工与衔接；不设部分的卷在卷级大纲中说明。
2. **实际章节层级。** 按 `volume.tex → part.tex → 章节及章内输入` 追踪活跃正文，保留章、节、小节直至 `subsubsection`、`paragraph` 等实际使用层级的标题与顺序。章号在卷内连续，不按部分重新编号；不遗漏拆分到其他文件中的正文。
3. **主要内容、论证与表述逻辑。** 每节及其下级小节都必须有实质说明，不留只有标题的条目。先用完整句子概括对象、问题和主要内容，再按正文实际顺序说明从何种情形进入、依据哪些定义或条件、通过什么推导、示例或比较得到什么结论，以及如何限定范围或承接后文。区分定义、证明、直觉和经验说明；正文没有给出证明时，不在大纲中写成已证明。只列标题、方法名称、公式名称或通用的“先定义、再分析、最后总结”不算完成大纲。
4. **实际完成状态。** 只有部分标题而未接入章节的入口，应明确写明尚无章节正文和可归纳段落；不把拟设章节列为已有正文。不编号的阅读指引在所属部分说明，不计入正文章数。

`plans/` 中的大纲是当前正文的提要，不能替正文补入尚未展开的方法、论证或结论。发现旧大纲与正文不一致时，以当前活跃正文修正大纲；新增内容须先落实到正文及所属入口，再据实际内容更新大纲。拟调整稿可以先提出新的组织和展开计划，但须按上文要求单独保存并声明状态。

## 大纲的写作组织

### 先确定同层分工和父子归属，再安排顺序

组织章、节及下级内容时，先说明上位问题，再确定各分支分别回答什么，以及按什么共同依据分组：

- **同层分工。** 同一父标题下的主体分支须有可说明的共同划分依据，职责和抽象程度相当。进入下一层时可以换用适合该问题的依据，不要求全章始终使用一种分类。共同基础、综合比较与章末小结承担准备或收束作用，应说明与主体分支的关系。
- **父子归属。** 子项应具体化或支撑父项，父标题应覆盖其实际内容。不要把一般概念与其特例当作同一分类下的并列类别，也不要把属于某一性质的判别或应用散放到无关分支下。多个分支共用的内容确定主要讲解位置，其他位置说明当前用途并准确回指。
- **覆盖与重复。** 检查每个分支是否有独立职责、必要方面是否缺失，以及同一内容是否被重复展开。再次使用同一概念或例子时，写明新增的比较、条件或解释任务；不能仅因换了标题就重复定义或论证。
- **依赖顺序。** 分工和归属成立后，再按概念、证明及使用依赖安排阅读顺序。“后者要用前者”只能说明先后，不能证明二者同类或应从属于同一父项。真实的证明步骤、算法流程或认识阶段可以顺序组织，但须说清每一步的职责和推进关系。

标题直接指出对象、性质、操作或比较关系。先核对实际内容是否归位，再判断标题能否概括职责；不为形式整齐换成更抽象的名称，也不靠过渡句掩盖归属错误。

### 区分 paragraph 标题与自然段

`paragraph` 是有标题的内容单元，自然段是在该单元内展开说明和推理的文本段落，两者不能混用：

- 一个 `subsubsection` 内有多个需要分别辨认的主要内容时，用 `paragraph` 组织，并在大纲中以独立标题显著标为 `paragraph：具体标题`，保留与上级的层级关系。已有正文大纲按实际标题登记；拟调整稿则说明建议的结构。
- 一个 `paragraph` 围绕一个主要内容展开，可以包含多个自然段。自然段数量取决于解释和推理需要，不把一个较长的定义、证明或讨论强行压成一段。
- 支撑定义的例子、证明中的中间步骤和局部说明可以各占自然段，不必各设 `paragraph` 标题。若一组示例承担独立的解释任务，可以合为“某概念的示例”这一 `paragraph`，再在内部逐段展开。
- 只有一条完整论述线的小节可以直接组织自然段，不为凑齐层级增加标题。不要把每个自然段都升成标题，也不规定每个 `subsubsection` 必须拆出固定数量的 `paragraph`。

### 按自然段写清内容与衔接

每个 `paragraph` 下按实际展开顺序编号列出自然段提要；没有 `paragraph` 标题的完整论述，直接在所属小节下列出。编号表示自然段的安排，不是新增一层正文标题。

每项提要用完整句子写清本段讨论的具体内容、所用条件或依据，以及要得到的认识。涉及公式、定义、构造、比较或示例时，说明准备解释哪些关键步骤；“介绍定义”“给出示例”“证明结论”等标签不能代替内容。

相邻提要还须说清前后关系：承接前一段的哪个对象或结论，补上什么尚未解释的步骤，改变什么条件，或转向同一问题的哪个并列方面。可以在当前项或相邻项中自然交代，不要求每项套用固定栏目，也不能只用“首先、其次、最后”表示逻辑。

对于新概念，应安排从已有对象或具体问题到直观含义、正式定义及必要解释的过程；对于论证，应写出从前提到结论的关键中间步骤及其依据；对于示例，应交代对象、操作、结果和所说明的关系。例子可以先于定义建立直觉，也可以在定义后检验理解，依实际任务安排，不机械套用同一种顺序。仅审读大纲时，核查这些展开计划是否充分，不把计划清楚等同于正文已经讲清。

不能为缩短大纲省略必要条件、对象转换或中间推理，也不能把尚未解释的步骤交给读者猜测。较长过程可拆成多个自然段；跨节使用已有结论时，说明当前所需的结论、适用条件及用途。

### 写法示例

以下示范拟调整大纲中的层级与自然段提要，示例数量和段数不作为模板：

```markdown
##### 子空间度量

###### paragraph：子空间度量的定义

1. 从只考察度量空间中一个子集的问题进入，说明希望保留原有的两点距离，只限制允许比较的点；由此提出子空间度量要定义什么。

2. 给定度量空间$(X,d)$及子集$A\subseteq X$，定义$d_A=d|_{A\times A}$。说明在$A$中选取的点仍属于$X$，据此逐条解释度量公理如何继承，得到子空间$(A,d_A)$。

###### paragraph：子空间度量的示例

1. 先取实轴中的区间，说明两点间的距离仍为绝对值之差；端点是否属于区间改变可选点的范围，不改变已选两点的距离公式。

2. 再取欧氏空间中的球面，说明继承的欧氏距离是两点间的弦长。与前例对照，区分限制点的范围与重新定义距离，并指出沿球面路径的距离需要另行定义。

3. 回到两个例子的共同变化：子空间中可出现的点受到限制。由此引出后续相对邻域的讨论，说明下一步需要考察子空间球与环境球的关系。
```

## 正文修改时同步维护

每次修改正文都必须复核对应大纲，不能只在移动章节或改标题时检查。修改前阅读所属部分大纲及相邻正文，确认已有主线、内容边界和依赖；修改后按最终正文逐项核对：

- 标题、层级、顺序、卷内编号及源文件链接是否仍准确；
- 段落提要是否覆盖新增、删除、合并或转移的主要内容；
- 对象、假设、适用条件、方法、推导、结论及局限的变化是否已反映在提要中；
- 相关部分的职责、章节衔接、阅读指引和总索引是否需要同步调整。

即使标题未变，只要主要论述发生变化，也必须更新对应提要。仅调整措辞或排版且不改变上述内容时，仍须确认现有大纲准确，无需制造无意义的文字差异。内容跨部分或跨卷移动时，同时检查移出与移入两侧的大纲和索引。

## 验收与提交

交稿和提交前，按实际正文入口复核覆盖范围、标题顺序、段落提要与所有相对链接。相关结构审计可以辅助检查，但不能代替对段落内容的核对；编译通过也不代表正文与大纲一致。

再按“大纲的写作组织”分别核对同层分工与父子归属、依赖顺序、`paragraph` 标记和自然段衔接。拟调整稿依据声明的基线与调整范围验收，交付时明确哪些是建议、哪些已落实到正文。

正文与需要更新的大纲、索引必须在同一任务 worktree 中完成，并纳入同一项变更一并交付、暂存和提交，不把大纲同步留作后续任务。交付说明应报告已核对大纲一致性；未改动大纲时，说明已确认现有提要仍适用。构建与成品校验仍按[开发要求](development.md)执行。
