# 开发规范

本目录中的规范适用于本项目的所有 LaTeX 内容、公式、图像和工程文件。新增或修改内容前，应阅读与任务相关的规范；若不同文档之间存在冲突，以更具体的规范为准，并在提交前消除歧义。

## 规范索引

- [开发要求](development.md)：worktree、分支、并行协作、提交、集成及清理。
- [LaTeX 与数学记号规范](latex.md)：文件组织、符号、公式、宏、引用与编译检查。
- [图像规范](figures.md)：框图的模型设计与 TikZ 还原、品质参考、语义图标及标题/说明层次、Matplotlib 数据图、生成式插画与可复现性。
- [中文写作规范](writings.md)：问题驱动的概念铺陈、逻辑衔接、自然中文、术语、引用、改写示例及交稿检查。
- [书籍样式规范](design.md)：字体与配色、前置页、语义环境、边注引文及图表用法。

## 通用原则

1. 一致性优先。同一个概念在全书中使用相同的名称、符号和视觉编码。
2. 定义先于使用。术语、符号和缩写首次出现时必须定义。
3. 内容必须可追溯。外部结论、数据和非原创图像应注明来源。
4. 产物必须可复现。公式、图表和实验结果应能从源文件或明确记录的生成过程重新得到。
5. 修改应保持聚焦。不要在同一变更中混入无关的格式化或大范围重排。
6. 不确定时沿用相邻章节和既有宏的风格；确需引入新约定时，先更新本目录中的规范。
7. 文字质量必须单独检查。涉及正文、大纲、图表说明或示例文字时，必须阅读并执行 [中文写作规范](writings.md)；相邻章节的旧写法不能成为沿用突兀、空泛或机械表达的理由。
8. 开发任务必须使用独立 worktree 和分支。主工作区用于基线查看和变更集成；各任务独立修改、构建与提交，不共享可写构建目录。
9. 计划只保留现行结构、未实施的大纲、可追溯的选材资料和未完成任务，入口见 [计划索引](../plans/README.md)。正文结构变化时同步更新大纲、章目映射及相关说明；编号必须注明所属出版单元或局部范围。已完成任务的聊天讨论、阶段审读、旧行号与一次性构建报告从工作树移除，历史由 Git 保存。删除过程材料前提取仍有效的待办，并检查脚本和文档依赖；图源、数据、生成提示词、许可证及仍使用的机器校验契约继续保留。
