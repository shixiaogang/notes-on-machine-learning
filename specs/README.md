# 开发规范

本目录中的规范适用于本项目的所有 LaTeX 内容、公式、图像和工程文件。新增或修改内容前，应阅读与任务相关的规范；若不同文档之间存在冲突，以更具体的规范为准，并在提交前消除歧义。

## 规范索引

- [开发要求](development.md)：worktree、分支、并行协作、提交、集成及清理。
- [LaTeX 与数学记号规范](latex.md)：文件组织、符号、公式、宏、引用与编译检查。
- [图像规范](figures.md)：三类图选型、全书低饱和度配色、情境插画与历史时间线风格、尺寸与圆角、系列一致性、标注及可复现性。
- [中文写作规范](writings.md)：写前组织、各类内容的写作动作与合格依据、表达与引用、三遍复读、问题关闭及交付条件。
- [正文大纲与计划目录规范](plans.md)：当前正文大纲与拟调整稿的边界、同层分工与父子归属、`paragraph` 与自然段提要、同步维护及验收。
- [书籍样式规范](design.md)：字体与配色、前置页、语义环境、边注引文及图表用法。

## 通用原则

1. 一致性优先。同一个概念在全书中使用相同的名称、符号和视觉编码。
2. 定义先于使用。术语、符号和缩写首次出现时必须定义。
3. 内容必须可追溯。外部结论、数据和非原创图像应注明来源。
4. 产物必须可复现。公式、图表和实验结果应能从源文件或明确记录的生成过程重新得到。
5. 修改应保持聚焦。不要在同一变更中混入无关的格式化或大范围重排。
6. 不确定时沿用相邻章节和既有宏的风格；确需引入新约定时，先更新本目录中的规范。
7. 文字质量必须单独检查。涉及正文、大纲、图表说明或示例文字时，必须阅读并执行 [中文写作规范](writings.md)；相邻章节的旧写法不能成为沿用突兀、空泛或机械表达的理由。
8. 开发任务默认使用独立 worktree 和分支。主工作区用于基线查看和变更集成；各任务不共享可写构建目录。同一任务 worktree 可由多个 writer 协作，但写入范围、暂存、提交和构建必须协调并串行处理。
9. `plans/` 默认保存总索引和按卷、部分组织的当前正文大纲；用户指定的数学基础五卷目标目录单独保存在 `plans/mathematical-foundations/`。两类材料的范围与实施状态分别维护，具体遵循[正文大纲与计划目录规范](plans.md)。每次正文修改均须核对并同步标题、顺序、段落提要及受影响的索引，正文与大纲作为同一项变更交付和提交。旧规划与过程材料由 Git 保存；仍有效的校验契约及复现资源按用途迁至相应目录，清理前检查依赖。
