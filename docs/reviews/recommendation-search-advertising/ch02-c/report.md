## 主要发现

### CH02-C-R1：LONGER被误述为逐层缩短序列

| 字段 | 证据记录 |
| --- | --- |
| 严重程度/状态 | 主要；已核实问题 |
| 维度 | 内容与论证正确性、图表呈现 |
| 位置 | 正文L401-406，`sec:rs-longer`；表2.2的LONGER行L516；PDF物理页38-39、42 |
| 原句 | “再逐层降低后续的序列规模”；标题“逐层压缩”；表行“局部合并、逐层压缩” |
| 外部证据 | [LONGER v2](https://arxiv.org/abs/2505.04421v2)，实际读取§3.4-3.5.4、PDF第5页原图。式(12)为`CrossAttn(O,R) -> SelfAttn(.) × N`，前者标为“compress long sequence”，后者标为“high-order interactions”；§3.5.3说明后续层在采样后序列上计算 |
| 问题与影响 | 原方法是局部TokenMerge及首层查询压缩，随后堆叠自注意力；所核验版本没有各后续层继续减少位置数的操作。当前概括会使读者错误重建网络层次与成本来源，且错误进入比较表 |
| 反证核对 | L404后半句其实正确说明“首层”与“后续在缩短的序列上继续编码”。原§3.5.4虽名为Stacking and Compression，但不能据此把表示逐层改进解释为序列逐层缩短 |
| 最小修订 | 同步修标题、首段和表行；用一条短的长度/形状关系区分局部合并、首层少查询读长历史、后续保持压缩后位置数的编码，不必扩写系统实现 |

### CH02-C-R2：TOP1说明混淆分数平移与训练中的抬分趋势

| 字段 | 证据记录 |
| --- | --- |
| 严重程度/状态 | 次要；已核实问题 |
| 维度 | 内容与论证正确性、结构与文字表述 |
| 位置 | L79-88，`eq:rs-gru4rec-top1`；PDF物理页27 |
| 原句 | “第二项把负例得分向零约束，避免只靠整体抬分降低相对比较项。” |
| 证据 | 第一项为`sigmoid(s_negative-s_positive)`；两分数同加常数时完全不变。例如(1,2)与(11,12)均得0.268941。[GRU4Rec](https://arxiv.org/abs/1511.06939)实际读取§3.1.3、PDF第5页：动机是某些正物品又充当其他样本的负例，训练可能不断推高得分，故约束负例靠近零 |
| 影响 | 读者会误以为整体平移可以改善成对排序项，混淆绝对分数约束与相对排序 |
| 最小修订 | 保留正确公式及“负例向零约束”，将动机改为限制绝对得分漂移，并保留正负物品跨样本复用的条件 |

| 字段 | 证据记录 |
