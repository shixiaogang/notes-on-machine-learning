### CH02-B-01：DETR的L1项沿用了未转换的角点坐标约定

- 严重程度：主要。
- 维度：内容与论证正确性。
- 位置：`tex/04-applications/02-image-processing/02-image-recognition-and-retrieval.tex` L111、L180—190；式 `eq:vision-detr-matching`；PDF物理27、29—30页。
- 原文短引：L111“以下采用连续边界 b=(x1,y1,x2,y2)”；L190只补充“框在共同归一化坐标中比较”。
- 问题：本章先将框向量定义为两个角点，DETR节没有重新定义参数化，读者因而会在角点坐标上计算L1。原始DETR的L1对象是归一化中心位置与宽高，GIoU才需要转换为角点。两者不能仅靠“共同归一化”视为等价。
- 可核验证据：[DETR原论文](https://arxiv.org/pdf/2005.12872) §3.1，PDF第5—6页；[作者matcher实现](https://github.com/facebookresearch/detr/blob/main/models/matcher.py)直接对中心宽高执行 `torch.cdist`，仅在GIoU调用前执行 `box_cxcywh_to_xyxy`。独立反例中，同一目标对两个预测使用5×L1+2×GIoU损失，中心宽高代价为5.125和5.416667，角点代价为4.875和4.666667，选择发生反转；输入及计算见底稿。
- 影响：读者照正文实现会改变匹配和坐标监督，而不仅是输出显示方式。现有预设代价矩阵算例虽正确，但没有暴露这一差异。
- 最小修订方向：在DETR节明确引入归一化中心宽高向量，写清由角点转换的关系，并说明计算GIoU时转回角点；保留当前“匹配用概率、训练用负对数概率”的正确区分。
- 核验置信度：高。

### CH02-B-02：Mask2Former缺少可执行的掩码更新与三任务输出恢复

- 严重程度：主要。
- 维度：深度理解与洞察（机制与条件）；内容与论证正确性（退化条件）。
- 位置：同一正文文件L275—288；`sec:vision-recognition-mask2former`；PDF物理33—34页。对应大纲L275—279。
- 原文短引：L286“允许读取为0，不允许为负无穷，再作softmax”；L288“可以按类别汇总成语义图，也可保留实例，或通过类别和重叠处理形成全景图”。
- 问题：关键接口仍停留在操作名称。正文未说明初始查询如何得到第一张掩码、上一层软掩码如何按当前特征尺寸与阈值转为读取范围，也未处理整行全屏蔽。最终恢复只列三种任务名称，读者不能据此从一组类别分数与掩码算出语义、实例和全景结果。
- 可核验证据：[原论文](https://arxiv.org/pdf/2112.01527) §3.2.1，式2—3说明初始掩码、尺寸调整和0.5二值阈值；[作者解码器](https://github.com/facebookresearch/Mask2Former/blob/main/mask2former/modeling/transformer_decoder/mask2former_transformer_decoder.py)在每层将全屏蔽行重置为不屏蔽。若前景为空，正文规则会让指数均为0，softmax分母为0。[作者恢复实现](https://github.com/facebookresearch/Mask2Former/blob/main/mask2former/maskformer_model.py)中，语义输出按类别概率与掩码概率加权求和；全景输出还需逐像素竞争、过滤和同类stuff合并；实例输出保留候选身份。
- 影响：读者既无法处理合法的空预测，也无法理解统一预测接口究竟怎样产生不同成果。L288关于“不同任务分别训练”的边界是正确的，但不能代替恢复步骤。
- 最小修订方向：补一段初始掩码、阈值、尺寸对齐及空行兜底；用两查询、少量像素展示三种恢复的不同操作。不要求复现完整实现或新增大型架构图。
- 核验置信度：高。这里报告的是教材解释缺口，不是声称Mask2Former原模型会因空掩码而必然失败。

### CH02-B-03：SAM多候选掩码的关键训练机制没有解释

- 严重程度：主要。
- 维度：深度理解与洞察（机制与条件）。
- 位置：同一正文文件L293—297，重点L295；`sec:vision-recognition-sam`；PDF物理34页。对应大纲L281—285。
- 原文短引：“训练提供图像、目标掩码与采样提示，歧义输出通过多个候选容纳一个提示的不同合理解释。”
- 问题：正文给出多个候选与质量估计，却没有解释训练为何能保留不同解释。仅增加输出头、对所有候选施加同一目标，并不能说明多候选的分工怎样形成。这个步骤正是小节标题中“歧义掩码”的核心，不属于可直接回指通用注意力的细节。
- 可核验证据：[SAM原论文](https://arxiv.org/html/2304.02643v1#S3) §3 “Resolving ambiguity”说明通常输出3张掩码，训练时只对最小掩码损失反向传播；另用预测IoU给候选排序。“Losses and training”说明掩码监督使用focal与Dice的组合。
- 影响：车门与整车的例子能说明使用时为何需要选择，却没有回答训练如何容纳这种歧义，读者难以重建该教学过程。
- 最小修订方向：补充最小掩码损失分支的选择与反传，用三个候选损失的小例子说明；保留质量头估计重叠质量、用户通过交互明确意图的区别，不把质量分数当作理解用户意图的保证。
- 核验置信度：高。属于解释不完整，不将现有文字判为对SAM原算法的直接错误陈述。

### CH02-B-04：DUSt3R置信损失的求和作用域不清

- 严重程度：次要。
- 维度：内容与论证正确性。
- 位置：同一正文文件L461；`sec:vision-recognition-dust3r`；PDF物理40页。
- 原文公式：`\sum_i c_i e_i-\alpha\log c_i`。
- 可核验证据：按通常运算作用域，减项在求和外，留下自由下标i。[原作者 `ConfLoss.compute_loss`](https://github.com/naver/dust3r/blob/main/dust3r/losses.py)先逐点计算 `loss * conf - alpha * log_conf`，再归约；对数惩罚必须覆盖每点。
- 影响：文字希望说明每个点的置信权重，但当前总损失写法不唯一，可能被误读为只对一项加惩罚。
- 最小修订方向：用括号将误差与对数项共同置于求和内。若继续解释“趋于零”，注明这是放宽为c>0的通用动机；[原文§3.2](https://arxiv.org/html/2312.14132v3#S3.SS2)实际采用c=1+exp(raw)>1，不能把零塌缩当作该参数化真实允许的取值。
- 核验置信度：高。

### CH02-B-05：GeM“在平均与最大之间”的说法超出所给指数范围

- 严重程度：次要。
- 维度：内容与论证正确性。
- 位置：同一正文文件L496—502；式 `eq:vision-gem`；PDF物理41页。
- 原文短引：“在两者之间调节”，随后公式仅要求 `q_k>0`。
- 可核验证据：沿用正文输入(1,1,1,4)，取允许的q=0.5，GeM=1.5625，小于算术平均1.75，不在平均1.75与最大4之间。[原论文§3.2](https://arxiv.org/pdf/1711.02512)给出幂均值及q=1、趋于无穷的两个特例；正文q=3的2.559算例本身正确。
- 影响：读者可能错误概括整个q>0区间，尤其当指数可学习时会误判其约束和含义。
- 最小修订方向：把“平均到最大”的解释限定在q≥1，或补充0<q<1会更偏向小响应。
- 核验置信度：高。
